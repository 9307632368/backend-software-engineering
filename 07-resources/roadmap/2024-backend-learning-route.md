# Backend learning route (2024 portfolio)

My order is to learn a concept, write a tiny API, deliberately break it, test it and then use it in a larger system.

| Stage | Sections | Practical checkpoint |
|---|---|---|
| 1 | `01-fundamentals/tutorials` | Route, validate and handle HTTP responses |
| 2 | `01-fundamentals/examples` | Authentication, SQL relationships, uploads and caching |
| 3 | `01-fundamentals/exercises` | Solve tasks without copying the answer first |
| 4 | `02-intermediate-concepts` | Modular APIs, background work and integrations |
| 5 | `03-advanced-concepts` | Transaction safety, resilience and system design |
| 6 | `04-industry-level-projects` | Order, ticket and booking backends |
| 7 | `05-interview-preparation` | Explain trade-offs and implement edge cases |
| 8 | `06-real-world-case-studies` | Diagnose failures in simulated scenarios |
| 9 | `07-resources` | Keep checklists, references and reusable scaffolding |

## What 'finished' means for a project

I can explain its API, data flow, trade-offs, failure scenarios, run commands and limitations. The repository has code that runs, a test suite, and a README that doesn't promise features that do not exist.

## Practice loop

1. Run code before changing it; record what passes.
2. Add a field or endpoint.
3. Write a test that fails before implementing the change.
4. Implement, rerun tests, and note the behavior.
5. Explain why my approach has limitations.

Keep commit dates real. Use the collection year as a curriculum grouping, not a claim that these projects were created in that calendar year.
